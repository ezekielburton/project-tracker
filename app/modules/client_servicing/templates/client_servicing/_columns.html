{# One macro per Client Servicing table column — each returns the exact markup for that column, unchanged from before this file existed. Which columns appear, and in what order, is driven by the `columns` list built in table.py (COLUMNS) and rendered by _table_rows.html — this file only answers "how do I render column X", never "which columns, in what order". That separation is what makes column resize/reorder possible without touching this file. Every carries data-col-key matching its column's key in COLUMNS — the reorder-drag JS (client_servicing.js) uses it to find and move each row's cell alongside its / when the user drags a header. Every also carries data-sort-value for click-to-sort: one flat, sortable primitive per column — an ISO date string for date columns, a raw number for numeric columns (never the formatted display text, which would sort "9" after "10"), a plain name string for person columns. Blank/missing values are always '', which client_servicing.js's sort always pushes to the bottom regardless of direction, so unset dates/values don't scatter through the middle of a sorted column. #}
